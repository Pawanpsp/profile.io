// Clean Architecture · Kotlin · Flow
@HiltViewModel
class UrlFilterViewModel @Inject constructor(
    private val engine: UrlFilterEngine
) : ViewModel() {

    private val _result = MutableStateFlow<UiState>(Idle)
    val result = _result.asStateFlow()

    fun checkUrl(url: String) {
        viewModelScope.launch {
            _result.emit(Loading)
            val verdict = engine.checkURL(url)
            _result.emit(Success(verdict))
        }
    }
}

01 / PROJECT
eScan URL Filter SDK
Enterprise-grade Android SDK for real-time URL threat detection
Kotlin SDK AAR / Maven Security Coroutines
The Problem
Third-party Android apps needed a drop-in threat intelligence layer that could classify URLs — phishing, malware, spam — in real-time without introducing runtime crashes from conflicting transitive dependencies like Gson or Room version mismatches.
My Role & Solution
Sole architect and developer. Designed the SDK's public API surface, built a four-stage batch processing pipeline, and made deliberate dependency choices (plain SQLiteOpenHelper over Room) to eliminate host-app version conflicts.
Key Features
  • Suspend functions checkURL and checkURLBatch built on Coroutines + Flow for non-blocking, backpressure-aware threat checks.
  • In-flight deduplication via ConcurrentHashMap<String, Deferred<CloudResult>> — identical concurrent requests share a single cloud call.
  • Multi-layer caching with CacheManager: memory LRU → disk → cloud, reducing latency for repeat lookups by avoiding redundant network calls.
  • Custom FlexibleStringListAdapter (Gson JsonDeserializer) to handle polymorphic server responses returning either a String or JSON array without runtime crashes.
  • Consumer ProGuard rules packaged in AAR to protect SDK internals in any host app's minified build.

02 / PROJECT
VPN-Based URL Filtering App
Full-stack Android security suite with DNS-level content filtering
MVVM · Hilt VPN / DNS Room + SQLCipher TFLite ML
The Problem
Enterprise customers needed device-level URL filtering — blocking malicious or category-restricted domains — without requiring root access or a remote proxy. The solution had to work across all apps on the device, not just a browser.
My Role & Solution
Designed and implemented a local VPN service that intercepts all DNS traffic through a TUN interface. Built a 10-stage classification pipeline in the vpncore AAR library. Integrated on-device TFLite ML as a pre-cloud gate to reduce latency.
Key Features
  • 10-step DNS filtering pipeline: whitelist → LRU cache → encrypted DB → wildcard → regex → category → keyword → TFLite ML → cloud → default allow.
  • TUN file descriptor read/write loop built in vpncore AAR with DnsResponseBuilder computing correct IP/UDP checksums on synthesised block responses.
  • AES-256 encrypted local database using Room + SQLCipher, protecting sensitive domain lists and logs at rest.
  • MDM / Android Enterprise integration for remote policy push and WorkManager-based periodic sync of cloud rule sets.
  • Full MVVM architecture with Dagger-Hilt, Navigation Component, and a comprehensive test suite using JUnit5 + Mockk.
